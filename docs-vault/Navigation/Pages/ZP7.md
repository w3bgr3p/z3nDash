# ZP7

ZP7 показывает состояние задач, полученное напрямую от зарегистрированных ZP node-сервисов.

## Источник данных

z3nDash хранит только адреса узлов и их токены в таблице `zp_nodes`. Состояние задач запрашивается у каждого узла:

```text
GET http://HOST:PORT/state
Authorization: Bearer <token>
```

Токен берётся из строки регистрации узла (см. [[02. Добавление ZennoPoster воркера в локальной сети]])
и подставляется на стороне z3nDash: в браузер он не попадает. Узел, ответивший
`401`, помечен в списке **Unauthorized** — строку регистрации надо вставить заново.

Список узлов в окне **NODES** приходит через `GET /zp/nodes` с пробой: вместе
с доступностью узла там его версии `z3n7` и ZennoPoster, снятые с `GET /version`.
Отдельно те же данные отдаёт `GET /zp/version?machine=...`.

Страница получает адреса через `GET /zp/nodes?probe=false`, затем независимо
опрашивает каждый узел через `GET /zp/state?machine=...` каждые 3 секунды.
Задачи отображаются по мере поступления ответов: медленный или недоступный узел
не задерживает загрузку и обновление остальных. Одновременно выполняется не более
одного запроса состояния на узел; таймаут обращения к node — 10 секунд.

## Список задач

Доступны фильтры:

- имя;
- состояние;
- режим работы;
- теги.

Выбранные фильтры сохраняются в состоянии UI.

## Управление

Команды отправляются непосредственно выбранному node:

```text
POST http://HOST:PORT/command
```

Панель действий состоит из иконок, подпись каждой — в тултипе:

| Иконка | Действие | Команда |
|---|---|---|
| ▶ зелёная | запуск | `start` |
| ❚❚ жёлтая | пауза (задача останавливается, но не прерывается) | `stop` |
| ✕ красная | прерывание | `interrupt` |
| узел с двумя ветками | Input Settings | `set_input_settings` |
| ± | попытки: модалка с тумблером Set/Add, полем значения и кнопками +1 / +10 / +100 (они правят поле, команду шлёт Apply) | `set_tries`, `add_tries` |
| Clear ✓ / ✗ | сбросить успешные / сбросить неудачные | `clear_success`, `clear_fails` |
| терминал | Execution Settings | `set_execution_settings` |
| часы | Scheduler Settings | `set_scheduler_settings` |

Ещё есть apply/update settings и set threads из панели Limits.

## Панели

- Task Detail — параметры и действия выбранной задачи;
- Logs — логи выбранной задачи с её узла (`GET /zp/log`);
- allLogs — модальное окно [[Logs|общей истории]] со всех узлов, с фильтрами и сортировкой;
- traffic — модальное окно [[Traffic|HTTP-трафика]] со всех узлов и самого z3nDash;
- HTTP — трафик выбранной задачи: `GET /zp/traffic?machine=...&task_id=...`, опрос раз в 3 секунды;
- Projects heatmap — данные проектов из report API.

## Input Settings

`⚙ Input Settings` открывает переменные проекта. Значения приходят с узла как
`GET /zp/task/settings?machine=&task_id=` — пара base64: исходный XML
`InputSettings` и текущие значения.

Два вида, переключаются кнопкой в подвале окна:

- **Form** (по умолчанию) — виджеты по типам из XML:

  | Тип | Виджет |
  |---|---|
  | `Tab` | вкладка |
  | `Comment` | разделитель секции |
  | `Label` | подпись без поля ввода |
  | `Boolean` | чекбокс |
  | `Number` | числовой ввод |
  | `DropDown`, `Select` | выпадающий список |
  | `DropDownMultiSelect` | набор чекбоксов |
  | `Password` | скрытый ввод |
  | остальные (`Text`, `FileName`, `CaptchaModules`, …) | текстовое поле, длиннее 60 символов — textarea |

  Варианты для списков лежат в подписи блоком `{a|b|c}`; из показанной подписи он
  убирается. Рядом с подписью — ключ переменной, во всплывающей подсказке — `Help`.
- **JSON** — плоский объект `{ключ: строка}`.

Переключение переносит текущие значения, так что правки не теряются. Выбранный
вид запоминается. Если XML не разобрался, окно остаётся в JSON и показывает
причину.

Переменные, которые формой не рисуются, при сохранении не теряются: `Tab` и
`Comment` тоже бывают привязаны к переменной, поэтому значения с узла берутся
целиком, а поверх кладутся только те, что есть в форме.

`📋 Copy Payload` кладёт в буфер payload для [[Tasker|планировщика]]: `schema`
с описанием полей и `values` с текущими значениями.

Сохранение в обоих видах одинаковое — команда `set_input_settings` с исходным
XML и собранными значениями; XML пересобирает сам узел.

## API

- `GET /zp/nodes`
- `GET /zp/state`
- `GET /zp/state/all`
- `GET /zp/log`
- `GET /zp/traffic`
- `POST /zp/commands`
